## 1. はじめに：なぜこのツールを作るのか？

既存の「過去問データベース」は大問の画像切り出しや定期テストの作成には強いものの、日々の授業でサッと配る「10分〜20分の確認テスト」「朝の単語・漢字ドリル」「理社の基本用語チェック」には少し大がかりすぎた。

そこで、**「テキストと構造化データに特化し、20分で解き終わる1問1答形式の小テストを爆速で作って綺麗にA4印刷できる軽量ツール」** を目指してプロジェクトをスタートした。

## 3. 技術スタックの壁打ちと初期意思決定

ユーザーと話し合い、以下の4点が明確になった。

1. **フレームワーク**: Gemini APIキーをサーバー側で安全に隠蔽・管理できる **Next.js (App Router)** を採用。
2. **外部AIインポートとトークン削減**: ChatGPTやClaude、Gemini Web版に投げて得たテキストをコピペで取り込めるようにし、トークン消費が少ないフォーマットを設計する。
3. **スマート配点エンジン**: 設問数を変えた際にワンクリックで100点に均等配分し、端数（余り）も自動で綺麗に割り振るロジックを入れる。
4. **設計書とモック先行**: 本格的なコード生成の前に、まず `DESIGN.md` を作成し、ブラウザで直接触れるHTMLモックを作ってUI/UXを検証する。

## 4. UXの根本的パラダイムシフト（「人間は選択するだけ」への進化）

初期モック作成後、ユーザーから極めて本質的なフィードバックをいただいた。

> **ユーザー**:
> 「モックアップのデザインでいいが、問題の読み込みが多分この形ではない。原則問題はテキストからAIを用いて中身をぶっこ抜いてそれに答えや、問題のジャンルなどのメタデータを持たせて、UI上で問題形式などを指定してその中から検索された問題を選択して配置する方式がよい。
> UX向上が至上命題。このアイデアよりUXが向上するUIパターンある？
> 人間の仕事は、データとして蓄積された問題を選択するというところにしたい。
> また、数学はTeX系の表記を原則として、図形などはSVGなどで座標で管理する。」

### 設計の転換点
「1回ごとにテスト全体を生成して修正する」使い捨て型ではなく、
**「AIが問題をぶっこ抜いてプールに蓄積 ＋ 人間は選択するだけ」** という分離構造こそが教材作成の真の姿であると気づかされた。

これに対し、3つのUXパターン（A: カート選択、B: スロット自動充填＆スワップ、C: 類題ガチャ）をモック上でタブ切り替えできるように実装。
検証の結果、**「パターンB（スロット自動充填＆スワップ）」が正式採用**となった。

> **ユーザー**:

> このデータは、AIの自動生成をもととするがアプリ上で編集ができるようにはしておく」

### ここでの手戻りとUI改善
1. **カラム役割の再整理（3ステップUI）**:
   * 今まで「問題プール」と「配点状況（テスト編成）」の境界や目的が曖昧だった。

4. **アプリ上での直接編集モーダル（インライン修正）**:
   * AIが生成した問題でも、現場では「ちょっと数字を変えたい」「解説を足したい」という瞬間が必ずある。
   * 各スロットおよびプールカードに **「✏️ 編集」ボタン** を設置し、問題文・解答・配点・解説・サブ論点・タグをその場で手直しして即時反映できるようにした。

> あと、問題の配置で余白等を極力少なくするようにしたい。」

### 課題と設計改善
1. **プレビュー直接操作UI（インライン・アクションバー）**:

2. **極限まで余白を詰めるタイト組版（A4・1枚収容最適化）**:

## 11. 単一ドル記号（`$...$`）LaTeXレンダリング対応とAI出力ノイズ除去

* **課題**:
  * ユーザーが外部AIから出力したMini-JSON（中2数学「1次関数」「平行と合同」計61問）を取り込んだ際、数式部分が生テキストのまま表示され、KaTeX変換されない事象が発生。
* **原因の分析**:
  * 初期の `MathText.tsx` の正規表現が `$$ ... $$`（ディスプレイ）および `\( ... \)`（LaTeX標準）のみを対象としており、外部LLM（ChatGPTやGemini等）が標準的に出力する **単一ドル記号（`$ ... $`）** を拾えていなかった。
* **解決策**:
  * `MathText.tsx` に単一ドル記号（`\$[^$\n]+?\$`）のインライン数式パース処理を追加。
  * 外部AI出力に含まれる引用マーカー（`[cite: 3]` 等）を自動除去するサニタイズ処理を追加。
  * 改行エスケープ（`\n`）の正常反映を組み込み。
* **結果**:
  * `$x$`, `$y$`, `$y=70x+150$`, `$\frac{12}{x}$` などの数式・分数がすべて美しいKaTeX数式として即座に描画されることをブラウザで確認。
  * 提供された中2数学61問を問題プール（計64問）へ完全反映。

     - **大問の動的追加**: STEP 2下部に「+ 新しい大問を追加」ボタンを設置。
     - **大問の安全削除**: 各大問ヘッダーに削除（ゴミ箱）ボタンを配備。大問を削除すると含まれる設問が整理され、残りの設問で100点自動均等配分が即時再計算される。

     - カタカナ ⇄ ひらがな正規化、小文字化。
     - 「一次関数」「１次関数」「1次関数」「中二」「中2」などの入力で、問題文・単元名・サブ論点・タグ・解答の全フィールドを完全網羅してヒットさせる `fuzzySearchMatch` を実装。

     - 教科（ジャンル）タブの下に **メイン単元セレクタ（`availableTopics`）** を新設（例：「全単元」「1次関数」「平行と合同」など件数付き）。

     - **「タグ検索」クイック入力枠**: タグ一覧上部に専用のインクリメンタル検索窓を設置。ここにも表記ゆれ対応を適用し、「一次」と打つだけで「1次関数」「1次関数の定義」タグが即座に絞り込まれる。
     - **「単元別」グルーピング表示モード**: 全単元選択時でも、単元ごとに小見出しをつけてタグを整理・折りたたみ可能なモードを搭載。
* **実機検証結果**:
  - `fuzzy_search_ichijikansu_1788592401858.png`: 検索入力「一次関数」で「1次関数」の全47問が完全ヒットすることを確認。

## 35. 教材・PDFからのMini-JSON生成プロンプトの抜本的刷新（コードスニペット強制・単語テスト網羅・端折り厳禁）

* **日付**: 2026年9月26日
* **ユーザー要望**:
  1. 「mini json生成のプロンプトが雑魚い」
  2. 「１　コードスニペットで出力しない。」
  3. 「２　PDFに単語のミニテストっぽい問題がある場合それを無視してしまう。」
  4. 「３　勝手のPDFの中身を端折ってしまう。」
* **背景と課題**:
  - 従来のインポートモーダル（`ImportExportModal.tsx`）に表示されていたMini-JSON抽出プロンプトは、2行程度の極めて簡素な雛形（`以下の教材内容から問題を抽出し、以下の短縮JSON形式で出力してください（マークダウンや挨拶不要）。`）であった。
  - そのため外部LLM（ChatGPT / Claude / Gemini等）に教材PDFやテキストを投入した際、以下の3大問題が発生していた：
    1. **コードスニペットで出力されない**: マークダウン不要と指定していたため生テキストで返され、LLM画面で「Copy code」ボタンが出ずコピーが煩雑だった（類題プロンプトは既にコードスニペット指定済みだったが取込側は未対応だった）。
    2. **単語ミニテストの無視**: 欄外や章末、コラム、ウォームアップ、ステップチェック等に掲載されている単語テスト・一問一答・語句問題を「本文・付録」とみなして無視・スキップしてしまう。
    3. **勝手にPDF内容を端折る（間引き・要約）**: 問題数が多いPDFやテキストを渡された際、「以下省略」「代表的な問題のみ抽出」とAIが自己判断して省略してしまう。
* **実装内容**:
  1. **高精度教材抽出プロンプト生成モジュールの新設・強化 (`lib/importPromptUtils.ts`)**:
     - `buildMaterialExtractionPrompt(options?: MaterialPromptOptions)` を新設・大幅強化。
     - **Geminiの免責・逃げ封殺（マルチモーダル視覚解析エキスパート定義）**: 「テキストベースAIだから画像・PDFは処理できない」「一度に抽出できない」といった定型的な言い訳や会話文を固く禁止し、視覚レイアウト認識能力を発揮してMini-JSONのみを出力するよう厳命。
     - **コードスニペット出力の強制**: 前置きや挨拶を排除し、必ず ````json` コードブロック（コードスニペット）のみを出力するよう厳格に指示。ChatGPTやClaude、Geminiで「Copy code」ボタンが確実に出現し、ワンクリックでコピー可能。
     - **「単語・重要表現のまとめ」「重要語句チェック」の表・リスト完全問題化**: ページ上部・欄外・章末・コラムにある単語表や語句チェックを「単なる参考情報」と誤認させず、1単語・1表現 = 1問として必ず一問一答（"ly": "same-line"）としてJSON化するルールとFew-Shot例をプロンプト内に明示。
     - **完全網羅・端折り厳禁（Zero Omission）**: 「以下省略」「一部抜粋」「代表的な問題のみ」を絶対禁止とし、大問中の小問・枝問（(1), (2) や ①, ② 等）も1問ずつ分割して完全に抽出しきるルールをトップレベルで宣言。
     - **フォールバック情報の動的バインド**: モーダルで選択・入力された学年（`fallbackGrade`）、教科書名（`fallbackTextbook`）、タグ（`fallbackTags`）をプロンプトの初期値メタデータに動的埋め込み。
  2. **インポートモーダルUIの改善 (`components/ImportExportModal.tsx`)**:
     - `sampleAiPrompt` を固定テキストから `useMemo` による動的生成へ刷新。
     - プロンプトコピー枠に「```json コードブロック指定済」「単語表・重要語句も1語ずつ問題化」のバッジを表示。
     - **長大PDF分割Tipsの表示**: 16ページなどの長大なPDFを一括で投げてAIの出力トークン上限で破綻・拒絶されるのを防ぐため、「見開き1〜2ページ（1レッスン分）ずつ渡すと単語表や小問も一切取りこぼさず100%確実に抽出できる」という教員向けガイダンスを追加。
  3. **詳細設計書の更新 (`DESIGN.md`)**:
     - 「2.3 外部AI用コピペプロンプト標準テンプレート」に最新の高精度抽出プロンプト仕様を反映。
* **検証結果**:
  - `npm run build` による静的型チェック・本番ビルド通過（エラー0件）。

## 36. 問題インポート時の大問・セクション自動集約 ＆ 選択マージ機能（枝問統合UI）

* **日付**: 2026年9月26日
* **ユーザー要望**:
  1. 「これらを取り込んだ時に問題ごとにまとめる機能も欲しい」
* **背景と課題**:
  - 外部AIから出力されたMini-JSONにおいて、単語リスト（40問）や大問内の小問群が「1問1答（バラバラの個別オブジェクト）」として出力された場合、問題プールやStep 2でカードが細切れになり、テスト編成スロットへの配置や管理が煩雑になる課題があった。
  - 同一単元（`topic`）やサブ論点（`subTopic`）を持つ問題群を、取込時またはプレビュー画面でワンクリックで1つの大問（`(1), (2), (3)...` の枝問形式）に自動集約する機能、および好きな問題を選択してまとめる機能が求められた。
* **実装内容**:
  1. **自動グルーピング・マージエンジンの新設 (`lib/questionMergeUtils.ts`)**:
     - `autoGroupAndMergeQuestions(questions: Question[]): Question[]`:
       - 連続する同一セクション（`subTopic` または `topic`）の問題群を自動検出し、既存の `mergeQuestions` を用いて1つの大問オブジェクトへ非破壊マージ。
       - 問題番号を `(1), (2), (3)...` に自動リナンバリングし、`al: ["(1)", "(2)"]` や模範解答を統合。
     - `unmergeAllQuestions(questions: Question[]): Question[]`:
       - マージ済み大問を展開し、いつでもワンクリックで元のバラバラ問題配列に完全復元可能。
  2. **Step 1 取込画面での自動集約トグル (`components/ImportExportModal.tsx`)**:
     - フッターに「大問・単元ごとに自動集約（推奨）」チェックボックス（デフォルト: ON）を新設。
     - ONのまま「解析して枝問プレビュー・設定へ」を押すだけで、80問のバラバラJSONも一瞬で20個前後の教材通り美しい大問カードにまとまってプレビュー表示。
  3. **Step 2 プレビュー画面でのインタラクティブなマージ操作 (`components/ImportExportModal.tsx`)**:
     - **大問自動集約 & 全解除ボタン**: コントロールバーに「自動集約」「全解除」ボタンを配備。いつでも一括でまとめる／バラすの切り替えが可能。
     - **手動選択マージ（フローティングバー）**: 各問題カードにチェックボックスを設置。2問以上選択すると「選択した N 問を1つの大問にまとめる」アクションバーが出現し、自由な組み合わせで手動マージ可能。
     - **個別大問の分解**: マージ済み大問カードに「大問統合済 (N問)」バッジと「分解」ボタンを表示し、個別の大問だけをピンポイントで元に戻すことも可能。
* **検証結果**:
  - `npm run build` による静的型チェック・本番ビルド通過（エラー0件）。
